# Core — runtime-независимое ядро Transkreebatoriya

Здесь находится каноническое, не зависящее от runtime определение агента:
сценарии, ограничения, промпты и контракты. Конкретная упаковка (веб-сервис,
Docker, install-скрипты) живёт в `runtimes/<runtime>/`.

## Состав

| Файл | Назначение |
|------|-----------|
| `instructions.md` | Каноническое поведение агента: что должен и чего не должен делать |
| `prompts/postprocess.system.md` | Системный промпт LLM-редактора транскрибаций (версионируется через frontmatter) |
| `contracts/pipeline_contract.md` | Стадии пайплайна, статусы, математика прогресса и ETA, гарантии cleanup |
| `contracts/postprocess_contract.md` | Правила чанкования, think-strip, семантика LLM-постобработки |
| `contracts/error_contract.md` | Таксономия ошибок и их отображение на поведение системы |

## Сценарии

1. **Транскрибация с постобработкой (дефолт).** Пользователь загружает
   медиафайл → файл конвертируется в WAV 16 кHz mono → faster-whisper
   распознаёт речь → LLM-редактор исправляет пунктуацию, абзацы и спикеров →
   пользователь получает текст и скачивает `.md`.
2. **Быстрая транскрибация без постобработки.** Постобработка отключена —
   возвращается сырой текст whisper. LLM не требуется.
3. **Деградация без Ollama.** Если LLM-сервис недоступен, задача завершается
   с ошибкой постобработки, но сырой текст транскрибации сохраняется в
   результате задачи.

## Возможности

- Полностью локальная обработка: аудио не покидает машину.
- Поддержка форматов: `.mp3 .mp4 .wav .m4a .mkv .flac .ogg .webm .avi .mov`.
- Реальный прогресс и ETA на каждой стадии (см. `contracts/pipeline_contract.md`).
- Работа на CPU-only железе (INT8 whisper, маленькая LLM), опциональный CUDA.

## Ограничения (constraints)

- Без runtime-специфичных предположений о файловой системе в core-логике.
- Без встроенных секретов и environment-specific идентификаторов.
- LLM **редактирует** текст, но никогда не вычисляет факты и не меняет смысл
  («LLM narrates; scripts compute»): вся детерминированная логика —
  конвертация, распознавание, чанкование — в обычном коде.
- Состояние задач — временное: результаты не переживают перезапуск сервиса
  и ограничены TTL (см. `contracts/pipeline_contract.md`).
