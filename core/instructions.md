# Каноническое поведение Transkreebatoriya

Этот документ — нормативное описание поведения агента. Runtime-адаптеры
обязаны ему соответствовать; расхождение — это баг адаптера.

## Агент должен

1. Обрабатывать аудио локально: медиафайлы никогда не покидают машину
   пользователя (единственные внешние вызовы — скачивание моделей
   whisper/Ollama и опциональный Hugging Face Hub).
2. Отправлять текст транскрипции во внешний LLM-провайдер (OpenRouter)
   только при явном выборе пользователя (`LLM_PROVIDER=openrouter`);
   по умолчанию постобработка выполняется локально (Ollama).
3. Сохранять исходный смысл текста при постобработке: исправлять ошибки
   распознавания, пунктуацию, разбивку на абзацы и разметку спикеров, не
   добавляя и не убирая информацию (см. `contracts/postprocess_contract.md`).
4. Отдавать честный прогресс и ETA по фактическим данным обработки, а не
   по таймерам (см. `contracts/pipeline_contract.md`).
5. Валидировать входные файлы как можно раньше (формат — до записи на диск,
   размер — во время потоковой записи) и отклонять их с понятной ошибкой.
6. Удалять временные файлы задачи (исходник, WAV) после завершения обработки
   независимо от её исхода.
7. Ограничивать время жизни результатов: завершённые задачи удаляются по TTL,
   а не копятся в памяти бесконечно.
8. Сообщать об ошибках через типизированную таксономию
   (`contracts/error_contract.md`), а не через неструктурированные строки.

## Агент не должен

1. Отправлять аудио во внешние API — это неизменяемая граница core.
   Отправлять транскрипты во внешний LLM без явного согласия пользователя
   (дефолт провайдера — локальный).
2. Вычислять или домысливать факты с помощью LLM: модель только редактирует
   текст, все числа (прогресс, ETA, размеры) вычисляет детерминированный код.
3. Хранить секреты, токены и реальные environment-specific конфиги в
   репозитории — только `*.example` / `*.template` с placeholder-значениями.
4. Перезаписывать существующие локальные конфиги пользователя при установке.
5. Блокировать event loop долгими CPU/IO-операциями: тяжёлые стадии
   выносятся в пул потоков / подпроцессы.
6. Давать гарантии персистентности результатов сверх TTL задачи.
