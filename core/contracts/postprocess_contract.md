# Postprocess Contract — LLM-постобработка транскрибации

Нормативный контракт стадии постобработки. Реализация:
`backend/services/postprocess.py` + `backend/llm/`. Синхронность
проверяется `tests/test_postprocess.py`.

## 1. Роль LLM

LLM — **редактор транскрибаций**, а не генератор контента. Системный
промпт живёт в `core/prompts/postprocess.system.md` (версионируется через
frontmatter) и загружается из файла, а не зашивается в код.

**Normative rule:** промпт требует вернуть только обработанный текст, без
комментариев и пояснений. Реализация не должна пост-обрабатывать ответ
сверх описанного в §4 (think-strip): если модель «заговорила», это
проблема промпта/модели, а не повод добавлять парсеры.

## 2. Чанкование

- Текст длиннее `POSTPROCESS_CHUNK_CHARS` (дефолт 1800) разбивается на
  чанки по границам предложений (разделители — пробелы после `.!?`).
- Каждый чанк обрабатывается независимо тем же системным промптом.
- Порядок чанков в результате строго соответствует порядку в исходном
  тексте; чанки склеиваются через `\n\n`.
- Текст короче лимита обрабатывается одним запросом без разбиения.

## 3. Параллельность и таймауты

- Одновременно обрабатывается не более `POSTPROCESS_CONCURRENCY` чанков
  (семафор). Дефолт `1` — осознанно консервативный для CPU-only железа;
  повышение требует `OLLAMA_NUM_PARALLEL` на стороне Ollama.
- Таймаут одного чанка — `OLLAMA_TIMEOUT` секунд (дефолт 1800).
- Ошибка любого чанка валит всю стадию (partial-результаты не
  возвращаются — иначе нарушилась бы целостность текста).

## 4. Нормализация ответа

- Из ответа удаляются блоки `<think>...</think>` (chain-of-thought
  qwen3-подобных моделей), результат trim'ится.
- Для моделей с поддержкой флага `think` он явно выключается запросом.

## 5. Отображение ошибок

| Условие | Исключение |
|---------|-----------|
| LLM-сервис недоступен (connect error) | `OllamaUnavailableError` |
| Превышен таймаут чанка | `OllamaTimeoutError` |
| Прочие ошибки (HTTP 5xx, обрыв стрима, ...) | `PostprocessError` |

## 6. LLM-клиент

- Провайдер инкапсулирован за интерфейсом `LLMClient`
  (`backend/llm/base.py`); референс-реализация — `OllamaClient`
  (протокол `/api/generate` со стримингом).
- HTTP-клиент переиспользуется между чанками и задачами (единое
  соединение), а не создаётся на каждый запрос.

## 7. Out of Scope

- Склейка контекста между чанками (передача «хвоста» предыдущего чанка).
- Диаризация (настоящее определение спикеров) — разметка «Спикер N»
  делается LLM по контексту и точности не гарантирует.
