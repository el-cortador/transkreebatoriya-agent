# Error Contract — таксономия ошибок

Нормативная таксономия доменных ошибок. Реализация:
`backend/exceptions.py`; отображение на HTTP — в роутерах `backend/api/`.

## 1. Иерархия

```
TranscribatoriyaError                     # базовый класс
├── FileValidationError                   # формат / размер / пустой файл
├── ConversionError                       # ffmpeg: отсутствует, таймаут, код != 0
├── TranscriptionError                    # faster-whisper: файл не найден, сбой модели
├── PostprocessError                      # базовая ошибка постобработки
│   ├── OllamaUnavailableError            # LLM-провайдер недоступен (connect)
│   └── OllamaTimeoutError                # LLM-провайдер не ответил вовремя
├── TaskNotFoundError                     # task_id не существует
└── TaskNotReadyError                     # задача ещё не завершена
```

Имена `Ollama*` — исторические: исключения покрывают любой LLM-провайдер
(Ollama, OpenRouter). Переименование не делается ради обратной совместимости.

## 2. Отображение на поведение системы

**Normative rule:** ошибки стадий пайплайна (валидация после создания
задачи, конвертация, транскрибация, постобработка) **не пробрасываются в
HTTP** — они фиксируются в задаче: `status=error`, поле `error` содержит
человекочитаемое сообщение. Клиент узнаёт об ошибке через polling
`/api/status/{task_id}`.

| Ситуация | Канал | Код / состояние |
|----------|-------|-----------------|
| Неподдерживаемый формат при upload | HTTP | `400` |
| Пустой файл / превышен лимит при upload | HTTP | `400` |
| Несуществующий `task_id` | HTTP | `404` |
| Результат запрошен до `done` | HTTP | `400` |
| Сбой ffmpeg / whisper / LLM внутри задачи | задача | `status=error` + `error` |
| Неожиданное исключение в обработчике | HTTP | `500` |

## 3. Требования к сообщениям

- Сообщения ошибок — на русском, ориентированы на пользователя, не
  содержат traceback'ов и внутренних путей.
- Технические детали (stderr ffmpeg, коды возврата, исключения httpx) —
  в лог сервера, не в ответ клиенту.
