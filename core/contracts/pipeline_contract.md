# Pipeline Contract — стадии, статусы, прогресс

Нормативный контракт пайплайна обработки задачи. Реализация:
`backend/tasks/manager.py`. Синхронность кода и контракта проверяется
тестами `tests/test_process_task.py`.

## 1. Жизненный цикл задачи

```
pending → transcribing → processing → done
                                     ↘ error (на любой стадии)
```

| Статус | Значение |
|--------|----------|
| `pending` | Задача создана, обработка не началась |
| `transcribing` | Конвертация ffmpeg и/или распознавание whisper |
| `processing` | LLM-постобработка (только если включена) |
| `done` | Результат готов (`raw_text` + `processed_text`) |
| `error` | Обработка завершилась ошибкой, поле `error` заполнено |

**Normative rule:** статус `processing` наступает только при включённой
постобработке и непустом `raw_text`; иначе задача переходит из
`transcribing` сразу в `done`, а `processed_text` равен `raw_text`.

## 2. Математика прогресса

Прогресс — float 0–100, распределение по стадиям фиксировано:

| Стадия | С постобработкой | Без постобработки |
|--------|------------------|-------------------|
| Создание задачи | 0 | 0 |
| Конвертация ffmpeg | 1 → 5 | 1 → 5 |
| Транскрибация whisper | 5 → 75 | 5 → 100 |
| Постобработка LLM | 75 → 100 | — |
| Завершение | ровно 100 | ровно 100 |

**Normative rule:** прогресс монотонно не убывает в течение задачи
(допустимо стояние на месте, недопустим откат назад).

## 3. ETA

- ETA транскрибации вычисляется из фактической скорости обработки аудио:
  `eta = (длительность − обработано) × (прошло_времени / обработано)`.
- ETA постобработки — из среднего времени обработки одного чанка:
  `eta = avg(chunk_seconds) × оставшиеся_чанки`.
- `eta_seconds = null`, пока данных для оценки недостаточно; `0` — по
  завершении.

## 4. Гарантии cleanup

- Временные файлы задачи (загруженный исходник, сконвертированный WAV)
  удаляются после завершения обработки **независимо от исхода** (успех или
  ошибка).
- Завершённые задачи (`done`/`error`) живут в памяти не дольше
  `TASK_TTL_HOURS` (дефолт 24 ч), затем удаляются фоновым cleaner'ом.
- Перезапуск сервиса теряет все результаты — состояние in-memory, это
  задокументированное ограничение (см. `core/instructions.md`, п. 6
  «не должен»).

## 5. Out of Scope

- Очереди и лимиты одновременных задач: параллельные загрузки обрабатываются
  как есть, конкуренция за CPU/Ollama — на стороне окружения.
- Персистентность результатов на диске между перезапусками.
